§1

Summary

Quality-measure reporting depends on measure logic, value sets, and pipelines that change all year. Assurance that they still match the approved specification and governance policy happens mostly at submission time, so drift is found when a rate moves and audit evidence is rebuilt after the fact.

QI Sentinel treats measure integrity as a continuously monitored property of the platform. Deterministic scanners inspect measure logic, value-set references, Snowflake policy exports, logs, and lineage. Codex analyses what the scanners find, writes root-cause analysis and patches, and narrates evidence. A deterministic policy gate decides what happens: low-risk fixes go into a reviewable pull request, and anything touching measure meaning or requiring attestation goes to a human with the analysis already done.

The PoC proves this with one cycle against a synthetic platform seeded with four defects: find four, remediate two, escalate two, produce one evidence pack. It runs locally and from GitHub Actions.

QI-MASK-001 · Snowflakeauto-fix

Masking policy removed

PHI_MASK_DOB is no longer attached to PHI-tagged RPT.MEMBER_MEASURE.DOB. The fix restores the last approved policy: no semantic change, fully testable.

QI-LOG-001 · Cross-cuttingauto-fix

Member identifiers in logs

Synthetic MRN and DOB fields appear in measure-runner.log. The fix adds a redaction filter to pipelines/logging.yml.

QI-SEM-001 · Databricksescalate

Measure drift from spec

cbp_rate.sql pins VS_HYPERTENSION@2025 while the manifest says 2026, and excludes hospice but not palliative care. Both change who is in the population, so both go to Quality Analytics.

QI-LIN-001 · Cross-cuttingescalate

Lineage record missing

No run → source → output record for measure COL. The agent may draft a template, but evidence cannot be invented, so the data owner must attest.

Optional fifth seed. QI-FEED-001: supplemental clinical feed manifest missing for the current period in the Data Lake. Escalated to data engineering, because missing data cannot be auto-fixed.

Scanner shape

src/qi_sentinel/scanners/masking_policy.pypython
@scanner(rule_id="QI-MASK-001", layer="snowflake")
def masking_policy(ctx: Context) -> list[Finding]:
    tagged = ctx.catalog.columns(tag="phi")
    refs = ctx.snowflake.masking_policy_refs()   # {column_fqn: policy_name}
    return [
        Finding(
            rule_id="QI-MASK-001", severity="critical", confidence=1.0,
            target=col.fqn,
            expected=col.approved_policy,        # from the last approved snapshot
            observed=None,
            evidence=[ctx.artifact("mock-platform/lineage/catalog_tags.json"),
                      ctx.artifact("mock-platform/snowflake/policy_references.json")],
        )
        for col in tagged
        if col.fqn not in refs
    ]

# Key/value patterns only. A bare date pattern would flag every log timestamp.
SENSITIVE_FIELDS: dict[str, re.Pattern[str]] = {

    "dob": re.compile(r"\b(dob|birth_date)[=:]\s*\d{4}-\d{2}-\d{2}\b", re.I),

Codex analysis contract QI-SEM-001

A thin wrapper in src/qi_sentinel/agent/, the only module that imports the pinned beta openai-codex SDK, sends the measure file, the relevant spec section, and the value-set manifest entry to Codex with the prompt in .github/codex/prompts/monitor.md. The response must validate against this schema. If it fails validation, it becomes an analysis-error escalation rather than being dropped.

src/qi_sentinel/agent/codex_client.pypython
from openai_codex import Codex   # openai-codex, exact version pinned in pyproject.toml

def analyse_semantic(prompt: str) -> SemanticAnalysis:
    with Codex() as codex:
        thread = codex.thread_start()
        result = thread.run(prompt)
    # schema failure raises, and the caller records an analysis-error escalation
    return SemanticAnalysis.model_validate_json(result.final_response)

  QI-MASK-001: { auto_fix_allowed: true,  category: phi-protection }
  QI-LOG-001:  { auto_fix_allowed: true,  category: phi-protection }
  QI-SEM-001:  { auto_fix_allowed: false, category: measure-semantics,    route: quality-analytics }
  QI-LIN-001:  { auto_fix_allowed: false, category: evidence-attestation, route: data-governance }

allowlist:
  files:
    - mock-platform/snowflake/policies/**
    - mock-platform/pipelines/logging.yml
  commands: ["pytest", "sentinel verify"]

never_auto_apply:             # hard floor; rule config cannot override
  - measure-semantics
  - evidence-attestation
  - access-grant-widening

pull_requests:
  merge: never
Gate flip in the demo. Setting mode: observe and re-running produces the same four findings and analysis, but no branch or PR. Both fixes appear in the evidence pack as proposed patches marked "held: observe mode". This is also the mode the pilot starts in.

Workflow scan and remediate are separate jobs

.github/workflows/qi-sentinel.ymlyaml, abridged
on:
  schedule: [{ cron: "0 * * * *" }]
  workflow_dispatch: {}           # trusted triggers only; no pull_request_target

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions: { contents: read }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -e .
      - run: sentinel scan --no-remediate
        env: { OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }} }
      - uses: actions/upload-artifact@v4
        with: { name: evidence, path: artifacts/ }

  remediate:
    needs: scan
    if: github.repository == 'vzsundara/QICentinel_OpenAI'
    runs-on: ubuntu-latest
    permissions: { contents: write, pull-requests: write }
    steps:
      # checkout, setup, then the Codex Action step with the narrowest sandbox,
      # pinned to a commit SHA; confirm inputs against the Codex GitHub Action docs
      - run: sentinel remediate
      - run: pytest && sentinel verify

Idempotency. Each finding has a fingerprint (ruleId + target + expected) written into PR and escalation bodies. Before creating anything, the agent looks for an open record with that fingerprint and updates it instead.

§11

Architecture decisions

Recorded ADR-style so the pilot team inherits the reasoning, not just the code.

ADR-01

Read exported metadata, not live platforms

accepted
ContextLive Databricks and Snowflake add auth, cost, and setup time, and raise PHI-proximity questions during a hackathon.
DecisionScanners read files shaped like real exports (policy DDL, INFORMATION_SCHEMA JSON, lineage records) under mock-platform/. Live connectors implement the same collector interface later.
AlternativesSnowflake trial and Databricks Community connections. Kept optional.
ConsequencesFast, reproducible, zero PHI risk. The pilot must prove the connectors.
ADR-02

Code owns decisions; Codex owns reasoning and writing

accepted
ContextAuditors need repeatable dispositions. Model output varies between runs.
DecisionRule IDs, severity, thresholds, auto-fix eligibility, checksums, and test outcomes are deterministic code. Codex provides RCA, patches, plain-language findings, and evidence narration under a validated schema.
AlternativesOne agent prompt deciding everything: simpler, but not reproducible or defensible.
ConsequencesSame input, same disposition. Codex quality affects explanations and patches, never whether a change is allowed.
ADR-03

Python with the Codex Python SDK

accepted · v3.0, supersedes v1.0 and v2.0
Contextv1.0 chose Python for build speed. v2.0 switched to TypeScript to match the repo README and the TypeScript Codex SDK. The build lead is more productive in Python, and OpenAI now publishes an official Python SDK, openai-codex, currently in beta.
DecisionPython 3.12, pytest, pyproject.toml with a sentinel CLI. openai-codex pinned to an exact version and imported only in src/qi_sentinel/agent/. The Codex Action in CI is unchanged. Policy and specs stay YAML/JSON.
AlternativesTypeScript with the Codex SDK (v2.0). Community Python wrappers around the Codex CLI.
ConsequencesFaster build for this team with no loss of Codex-native tooling. Beta APIs may change before 1.0; the version pin and single wrapper module contain that risk.
ADR-04

Policy as versioned YAML with an allowlist and a hard floor

accepted
ContextCompliance owners must control agent autonomy and see who changed it.
Decisionconfig/policy.yml holds rule eligibility, confidence threshold, file and command allowlists, never_auto_apply categories, and merge: never. Changes go through PR review; the policy hash is in every evidence pack.
AlternativesDatabase-backed settings UI. OPA/Rego, which is the likely pilot upgrade.
ConsequencesAutonomy changes are Git history. The demo can flip mode live.
ADR-05

Evidence as hashed JSON plus HTML, with a verify command

accepted
ContextEvidence must be tamper-evident and readable by non-engineers.
DecisionCanonical evidence.json with SHA-256 over inputs, spec, policy, artifacts, and the pack; index.html generated from it; sentinel verify recomputes everything.
AlternativesAppend-only ledger or WORM storage: right for production, overbuilt for the PoC.
ConsequencesPortable and verifiable. Storage immutability deferred to the pilot.
ADR-06

Split scan and remediate jobs in GitHub Actions

accepted
ContextRemediation needs write access and an API key; scanning does not. Repo content is potentially adversarial prompt input.
DecisionScheduled or manual triggers only. scan runs read-only; remediate gets contents: write and pull-requests: write, runs only in the owning repository, and uses the narrowest Codex sandbox. Codex Action pinned by commit SHA.
AlternativesOne job with write permissions, which is simpler but widens blast radius.
ConsequencesFork content never runs with secrets or write access.
ADR-07

Value-set drift is escalated, not auto-fixed

accepted · changes README
ContextThe original README auto-fixed an outdated value-set OID. A new value-set version changes which members fall into the numerator or denominator, which contradicts gate condition 2.
DecisionFold value-set drift into QI-SEM-001 (escalate). Replace the auto-fix slot with QI-MASK-001, a Snowflake masking-policy restore.
AlternativesKeep the value-set auto-fix and weaken condition 2. Rejected: a quality analytics judge would catch it.
ConsequencesThe policy is internally consistent, the demo still shows 2 fixed and 2 escalated, and Snowflake coverage is restored.
ADR-08

CLI, PR, and evidence pack as the demo surface

accepted
ContextA dashboard competes with the core loop for build hours.
DecisionDemo the terminal run, PR #12, escalation #13, and the evidence HTML. Dashboard only after phase 5 is rehearsed.
AlternativesDashboard-first: polished, but risks a loop that does not work end to end.
ConsequencesMock E shows direction; it is not built by default.
§12

Safety and controls

ControlHow the PoC enforces it
Synthetic onlyAll member, claim, encounter, log data, and specifications are synthetic. Seeds are documented in test fixtures.
Control plane onlyScanners read code, configs, policy exports, and metadata. Nothing reads table rows.
Redact before reasoningLog samples are redacted during collect; Codex never receives raw log lines.
No fabricated evidenceLineage templates are marked unattested; the agent never writes historical records.
Bounded autonomySix gate conditions, allowlisted files and commands, never_auto_apply floor, merge: never.
Prompt-injection postureRepo files, issue text, commits, and PR content treated as untrusted input; dispositions never come from model output.
CI hardeningTrusted triggers, split permissions, no secrets or write access on fork content, Codex Action pinned by SHA.
NetworkAgent internet disabled during the demo; spec snapshots committed locally.
Publication hygieneLogs and evidence scanned for credentials and sensitive-field patterns before upload.
Claims boundaryReports conformance to supplied synthetic rules only; does not certify HEDIS, CMS, HIPAA, or audit compliance.

A pilot with real PHI needs privacy, security, legal, and compliance review, an applicable OpenAI agreement and BAA, eligible services, and approved endpoint and retention configuration.
